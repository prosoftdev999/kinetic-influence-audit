# LC-MS campaign influence audit

A process-development team is deciding whether an inherited isotope-tracing campaign is reliable enough to guide the next reactor block. The instrument exports and the paper log disagree, and the original analyst left before completing the handoff. Everything recovered from the campaign is under `/app/data/`: calibration injections, exported chromatograms, the reactor manifest, the withheld prediction schedule, the autosampler qualification, and the protocol notes.

Prepare a reusable `/app/solver.py` and run it to create `/app/result.json` as the team's machine-readable audit. The verifier may replay the solver on another campaign with the same file formats, chemistry, qualification rules, and incident classes but a different realization. The solver must read its input directory from `TASK_DATA_DIR` when set, defaulting to `/app/data`, and write to `TASK_OUTPUT` when set, defaulting to `/app/result.json`. When `TASK_REPLAY=1`, it may omit the expensive deletion-refit rows from `stability`; the replay still checks the independently recovered campaign incident, autosampler qualification, shared parameters, predictions, mass balance, and design decision.

Use the calibration injections to put every signal on a concentration basis, reconcile the training traces with the reactor conditions, and fit one shared kinetic description consistent with the recorded chemistry. Report the three transposed run-ID pairs, the two non-unit clock corrections, and the exchanging intermediate in `audit`. Each pair must be internally sorted, and the list of pairs must also be sorted.

The `parameters` object must contain exactly the ten quantities named in `schema.json`. Reference rate constants are expressed in min^-1 per mmol/L catalyst at 328.15 K; activation energies are in kJ/mol. The `predictions` array must cover every run and time in `prediction_times.csv`, with all eight isotopologues ordered A0, A1, B0, B1, C0, C1, D0, D1. Each row has `run_id`, `time_min`, `isotopologue`, and `concentration_mmol_L`, and the full array is sorted by run ID, time, then isotopologue order.

The autosampler qualification is part of the same release decision. Reconstruct it using `autosampler_nominals.csv`, `autosampler_sequence.csv`, and `autosampler_protocol.md`. Put the result in `sequence_audit` with `vial_order`, `carryover_fraction_polar`, `carryover_fraction_sticky`, `deep_wash_after_acquisition`, and `chi_square`. This is a joint sequence-reconstruction problem: all ten vials, both carryover-grid choices, and the single deep-wash boundary have to agree with the measured acquisition series under the protocol's chi-square rule.

Two decisions remain after the main reconstruction. First, follow `stability_protocol.md` to quantify how the fitted model moves when each complete exported trace is withheld. Put those results in `stability`, including the requested influential-run summary and all twelve deletion refits. Second, apply the follow-up selection rule in `lab_record.md` and return the chosen four candidate IDs, sorted, as `design_run_ids`. For deletion rows, use the exported trace IDs shown in `chromatograms.csv`; a solver that consistently carries the reconciled reactor IDs through that table is scientifically equivalent. Additional diagnostic fields are fine, but the required fields and values described above must still be present.

Use JSON numbers for every numeric value and keep full working precision. The reactor is closed, so concentration predictions must remain physically consistent with the charged amount. Do not infer concentrations by comparing raw peak areas from different acquisition sessions.

You have 3600 seconds to complete this task. Do not cheat by using online solutions or hints specific to this task.
